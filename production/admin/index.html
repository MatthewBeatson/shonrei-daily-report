SYNC BACKORDER DEMAND

A target is created, adjusted, or closed per SKU to match its total backordered quantity across every open SO (see production/README.md for the exact rules). This really does create/adjust/close a real Cin7 assembly once synced.

Pull from Cin7 -- same open-order selection as "Total Product on Order" above (AUTHORISED, not yet invoiced). Takes a couple of minutes the first time; review the per-SKU totals before syncing.

"Total on order" is this app's own figure (same logic as Total Product on Order above) -- what's still on order, EXCLUDING anything already invoiced even if Cin7 hasn't physically shipped it yet. This is what Sync targets below actually works from. Cin7 Allocated/on-hand (read live from Cin7's own product availability, not computed by this app) can run higher: Cin7 doesn't care about invoice status, so an order invoiced but not yet shipped still shows as Allocated (and its stock still shows in Cin7's on-hand) even after Total on order has already dropped it. The right-most column (red when above zero) is an ESTIMATE of that gap -- Allocated minus Total on order -- i.e. roughly how much is invoiced but still needs physically shipping in Cin7; it's arithmetic on the two figures already pulled, not its own confirmed Cin7 field, so treat it as a lead to check in Cin7, not a guaranteed-exact count. Click a column heading to sort by it.
